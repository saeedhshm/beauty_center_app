# القاهرة — الإدارة والكتالوج والعناوين

## القرارات المعتمدة والتنفيذ

- مدينة الإطلاق **القاهرة**، رمزها `EG-CAI`، العملة **EGP**، وتوقيت الأعمال **Africa/Cairo** (بما يشمل تغير التوقيت الصيفي، دون تثبيت offset يدوي).
- مهلة قبول الخبيرة الافتراضية **10 دقائق**، ومهلة الدفع بعد القبول **10 دقائق**، والعمولة **20%**. الثلاثة محفوظة في `settings.booking_policy` وقابلة للتعديل من API الإدارة.
- تطبيق التعديلات يغير إعدادات السياسة فقط، ولا يعيد كتابة لقطات الحجوزات أو `expires_at` التاريخية. محرك الحجز والـWorker سيستخدمان هذه القيم عند تنفيذهما؛ لا توجد مهام انتهاء حجز منفذة الآن.
- الدفع المطلوب Demo مع إمكانية ربط مزود لاحقًا. `/configuration` يعلن `paymentMode: demo`، لكن بدء دفعة وتأكيدها والاسترجاع **لم تُنفذ بعد**.
- المستخدم اعتمد العمل نهارًا فقط، وإتاحة الإلغاء والإكمال للعميلة والخبيرة، وإظهار العنوان دائمًا للخبيرة صاحبة الحجز. هذه متطلبات الحجز القادمة، وليست إذنًا للخبيرات باستعراض عناوين العميلات خارج حجوزاتهن.
- لم يُحسم وقت بدء/نهاية النهار ومدة الانتقال، حالات الإلغاء والإكمال وتوقيت الإكمال، وقت تثبيت السعر بين العرض والإرسال، الضريبة والتقريب، والاسترجاع وأهلية الصرف. **20% هي العمولة وليست نسبة ضريبة**. لا توجد معادلة ضريبية مخترعة.

## تغييرات التوافق والبيانات

- التسجيل وطلب OTP أصبحا للأرقام المصرية: `010/011/012/015` بإجمالي 11 رقمًا، أو الصيغة الدولية `+20`. تُخزن الهوية بصيغة E.164. هذا تغيير متعمد لعقد التسجيل السابق السعودي.
- الدخول يحتفظ بدعم أرقام حسابات العرض السعودية القديمة، دون السماح بتسجيل سعودي جديد. لا تُغير أرقام الحسابات القائمة أو جلساتها أثناء الترحيل.
- migration `0004_cairo_catalog_admin.sql` تغير defaults فقط للحجوزات والمدفوعات والتحويلات إلى EGP؛ الصفوف السابقة تحتفظ بعملتها.
- أضيفت عملة إلى أسعار الخبيرات: الأسعار القائمة قبل الترحيل تُوسم SAR، والأسعار الجديدة EGP. لا يوجد تحويل أسعار آلي. الكتالوج المصري لا يعرض عرضًا بعملة SAR؛ يمكن للخبيرة إعادة تسعيره صراحة عبر PUT.
- migration `0005_cairo_launch_policy.sql` تهيئ القاهرة والإعدادات المعتمدة دون استبدال إعدادات سبق وجودها. المدن القديمة والتاريخ لا تُحذف.
- migration `0006_booking_timezone_snapshot.sql` تضيف لقطة `time_zone` للحجز؛ الافتراضي الجديد Africa/Cairo. الترحيل يستخدم سياق المشروع السابق Asia/Riyadh للسجلات القديمة، وAfrica/Cairo لصفوف EGP التي بدأت مع التحول للقاهرة. لا تتغير `starts_at` أو `ends_at`، وعلى تفاصيل الحجز المستقبلية استخدام لقطته لا إعداد السوق الحالي.
- أضيف `auth_sessions.audience` لعزل جلسات المدير عن تطبيقات الهاتف، و`admin_audit_logs` لتسجيل تعديلات الإدارة داخل المعاملة نفسها. الإجمالي **17 جدول أعمال + 5 تقنية = 22 جدولًا**.

## APIs المنفذة

كل المسارات تحت `/api/v1`. العقد في `openapi.yaml` مع تفاصيل إضافية في `catalog.openapi.yaml`.

### دخول المدير

`POST /admin/auth/login`, `/admin/auth/refresh`, `/admin/auth/logout` و`GET /admin/me`.

- حساب المدير يُجهز خارج التسجيل العام. التسجيل العام لا يقبل `admin`.
- يستخدم Bearer access token وrefresh token في JSON، دون cookies أو اعتماد ضمني على جلسة المتصفح. جلسة `admin` لا تعمل في مسارات `mobile` والعكس، حتى إذا تغير دور الحساب في القاعدة.
- صلاحيات الإدارة تتحقق على الخادم. لا يمكن استعمال رمز هاتف للحصول على الإعدادات أو اعتماد خبيرة.
- واجهة Dashboard المرئية لم تُنشأ؛ الموجود APIs التي ستستخدمها. عند بناء الواجهة تُحدد إدارة الرموز الآمنة وCORS للـorigin المطلوب؛ لا يوجد تفعيل عام لـCORS حاليًا.

### الإعدادات والمدن والخدمات

- `GET /configuration`: مدينة الإطلاق، العملة، التوقيت، نمط الدفع، وbookingPolicy. لا يُرجع بقية جدول settings أو الأسرار.
- `GET /cities`: القاهرة إذا كانت مفعلة؛ لا تصبح المدن القديمة مفعلة في السوق الجديد لمجرد وجودها.
- `GET /services`: الخدمات النشطة.
- `GET/PATCH /admin/settings`: قراءة الإعدادات وتعديل الحقول الثلاثة فقط:

```json
{
  "acceptanceTimeoutMinutes": 10,
  "paymentTimeoutMinutes": 10,
  "commissionRate": "20.0000"
}
```

الدقائق من 1 إلى 1440 كحد إدخال تنفيذي، والنسبة نص عشري بين 0 و100 حتى 4 منازل. PATCH يسمح بحقل واحد أو أكثر. قفل سجل الإعدادات يضمن دمج تحديثين متزامنين لحقلين مختلفين دون فقد أحدهما، مع سجل تدقيق ذري.

- `GET /admin/cities` و`PATCH /admin/cities/:id`: عرض مدينة الإطلاق وتفعيلها/تعطيلها فقط؛ لا إدارة توسع متعدد المدن في هذا النطاق.
- `GET/POST /admin/services` و`PATCH /admin/services/:id`: الاسم والوصف والمدة والنشاط. تعطيل الخدمة لا يحذف حجوزاتها أو عروضها القديمة. PATCH لا يعيد تطبيق defaults الإنشاء.

### ملف الخبيرة والأسعار والاعتماد

- `GET/PATCH /experts/me`: الملف الحالي؛ التعديل يقبل الاسم والنبذة ومدينة القاهرة وحالة استقبال الحجوزات فقط. لا تعديل للدور أو الاعتماد أو وثيقة الهوية من هذا المسار.
- تفعيل استقبال الحجوزات يحتاج اعتمادًا `approved`. الاعتماد وحده لا يشغل الاستقبال تلقائيًا.
- `GET /experts/me/services` و`PUT /experts/me/services/:serviceId`: خدمات الخبيرة وأسعارها. السعر نص عشري بمنزلتين كحد أقصى، والعملة EGP من الخادم. لا مدة خاصة للخبيرة.
- `GET /admin/experts`: قائمة إدارية مع فلتر الاعتماد.
- `POST /admin/experts/:id/approve` و`/suspend`: اعتماد/تعليق الملف مع التدقيق. التعليق يوقف الاستقبال؛ الخبيرة تستطيع الدخول لقراءة حالتها.
- `GET /experts` و`GET /experts/:id`: كتالوج عام دون الحاجة إلى حساب. شروط الظهور: حساب خبير نشط، اعتماد approved، استقبال مفعّل، القاهرة مفعّلة، وخدمة واحدة نشطة على الأقل بسعر EGP.
- فلترة الخبيرات بالخدمة والمدينة والاسم. لا تُعرض أرقام الهاتف أو وثائق الهوية في الكتالوج العام.
- رفع الصور ومعرض الأعمال ووثائق الهوية الخاصة لم يُربط بمزود تخزين بعد.

### عناوين العميلة

`GET/POST /addresses` و`GET/PATCH/DELETE /addresses/:id` للعميلة الموثقة فقط. هوية المالكة من الجلسة، ومحاولة الوصول لعنوان طرف آخر تعيد 404.

- حقول الإدخال: `label`, `addressText`, `cityId`, `lat`, `lng`, `isDefault`. الإحداثيات نصوص عشرية اختيارية تُرسل كزوج أو null لكليهما.
- قفل حساب العميلة داخل المعاملة يجعل تعديل العنوان الافتراضي آمنًا تحت التزامن، بالإضافة إلى الفهرس الفريد في القاعدة.
- يُسمح بوجود صفر عناوين افتراضية؛ حذف الافتراضي لا يختار بديلًا تلقائيًا. حذف/تعديل عنوان محفوظ لا يغير لقطات حجوزات سابقة.

### Pagination والأخطاء

القوائم القابلة للتصفح تستخدم `page` (1–1000) و`limit` (1–50، الافتراضي 20)، وتعيد:

```json
{ "data": { "items": [], "pagination": { "page": 1, "limit": 20, "hasNext": false } }, "requestId": "..." }
```

الترتيب ثابت والاستعلام على الخادم. لا تُحسب إحصاءات كلية من صفحة واحدة. المدن والإعدادات والقائمة الخاصة بأسعار الخبيرة ليست بهذا الغلاف. أخطاء المدخلات 422، الجلسة 401، الدور 403، المورد غير المتاح/غير المملوك 404، المدينة أو الخدمة المعطلة والخبيرة غير المعتمدة 409.

## تشغيل العرض المحلي

داخل `web_app/backend`:

```sh
docker compose up -d --wait db
npm run db:migrate
npm run db:seed:demo
npm run dev
```

قاعدة التطوير المحلية هي `lamsa_dev` على `127.0.0.1:55432`، وتخزينها دائم عبر volume. seed مخصص لهذا الهدف المحلي فقط، ولا يُنفذ عند إقلاع API تلقائيًا.

حسابات العرض **الخيالية**:

| الدور | الهاتف المحلي | كلمة المرور التجريبية |
| --- | --- | --- |
| المدير | `01000000001` | `DemoAdmin-2026!` |
| العميلة | `01000000002` | `DemoCustomer-2026!` |
| الخبيرة | `01000000003` | `DemoExpert-2026!` |

توجد 3 خدمات تجريبية وخبيرة معتمدة تجريبية بأسعار 250.00 EGP للعرض. ليست هذه أسعارًا أو مدد خدمات تشغيلية معتمدة. seed لا يغير كلمات المرور أو الأدوار أو الاعتماد لحساب موجود، ولا يعيد ضبط الإعدادات عند تكراره. إذا كان رقم fixture مستخدمًا من قبل، يُترك كما هو؛ لا يُرقّى إلى مدير.

للتسجيل الجديد استخدمي رقمًا مصريًا مختلفًا وكلمة مرور من اختيارك وOTP العرض `123456`. لا SMS حقيقي ولا دفعات حقيقية في هذه المرحلة.
