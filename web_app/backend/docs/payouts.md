# المستحقات والتحويلات — المرحلة 8

## القرارات المعتمدة والتنفيذ

- الأهلية (مقترح موثق بانتظار اعتماد السياسة المالية): حجز `completed` + دفع `paid`
  غير مسترجع + `payout_id` فارغ. المكتمل بلا دفع (مسار `accepted→completed` المؤقت
  قبل الدفع) **غير** مؤهل — الاستحقاق يتبع التحصيل الموثوق.
- إنشاء التحويل `POST /admin/payouts` للإدارة فقط: `{expertId, bookingIds}` (1–200،
  فريدة). المبلغ دائمًا Σ `expertEarning` بعملة واحدة، محسوب هنا؛ أي mismatch في
  الخبيرة أو العملة أو الحالة أو الدفع أو الربط السابق يرد 409 ولا يُنشأ شيء.
- التزامن: صفوف الحجوزات تُقفل `FOR UPDATE` ويُعاد التحقق داخل المعاملة؛
  منشئان متزامنان لنفس الحجوزات ينتهيان إلى 201 + 409 `BOOKING_ALREADY_PAID_OUT`.
  FK المركب `(payout_id, expert_id)` يمنع ربط حجز بتحويل خبيرة أخرى على مستوى القاعدة.
- التحويل يبدأ **مسجلًا غير محوّل** (`transferredAt NULL`)؛ `POST /admin/payouts/:id/transfer`
  بمرجع تشغيلي يوثق التحويل اليدوي فقط — ليس تحويلًا مصرفيًا آليًا ولن يوصف بأنه كذلك.
  إعادة التسجيل تعيد السجل المخزن دون تغيير (idempotent). المحوّل ثابت لا يُعدل ولا تُضاف إليه حجوزات.
- الاسترجاع بعد الصرف: مرفوض بـ409 `BOOKING_IN_PAYOUT` حتى يُعالج التحويل تشغيليًا
  (المقترح المؤقت)؛ سجل `payouts` لا يُعاد حسابه تلقائيًا. راجع `payments.md`.
- كل إنشاء وتحويل يُدقق في `admin_audit_logs` داخل المعاملة نفسها.
- لا تغيير على الـschema: تصميم `payouts` وFK الحجز كانا كافيين؛ تحقق `db:generate`
  نظيف بلا migration جديدة.

## APIs المنفذة (تحت `/api/v1`)

- `POST /admin/payouts` — إنشاء تحويل مسجل (201) مع قائمة حجوزاته.
- `GET /admin/payouts` (فلترة `expertId, transferred`) و`GET /admin/payouts/:id` مع حجوزاته.
- `POST /admin/payouts/:id/transfer` — تسجيل التحويل اليدوي بمرجع.
- `GET /experts/me/payouts` و`GET /experts/me/payouts/:id` — تحويلات الخبيرة وحجوزاتها.
- `GET /experts/me/earnings` — ملخص محسوب على الخادم: `eligible` (مكتمل ومدفوع وغير
  مربوط) و`recorded` (مسجل غير محوّل) و`transferred`، مبالغ وعملات فقط دون تقديرات مضللة.
- الأخطاء: `BOOKING_ALREADY_PAID_OUT` و`BOOKING_IN_PAYOUT` (409) مع `INVALID_TRANSITION`
  و404 لغير المالك.

## التحقق

- `tests/integration/payouts.test.ts`: أربع رحلات على PostgreSQL حقيقي — إنشاء بمبالغ
  محسوبة ومنع الصرف المزدوج تحت منشئين متزامنين (201+409) مع تدقيق إداري، رفض غير
  المؤهل والخبيرة الخاطئة والأدوار، التحويل الثابت مع idempotent والملخص والملكية،
  وحظر الاسترجاع بعد الربط.
- لا تُعرض إجماليات التحصيل كأرباح منصة، ولا يُوصف تسجيل يدوي بتحويل مصرفي آلي.
