# التوفر والحجز — المرحلتان 4 و5

## القرارات التنفيذية (مقترحة وموثقة، بانتظار تثبيت ساعات النهار)

- النهار الافتراضي **09:00–22:00** بتوقيت القاهرة (`src/config/scheduling.ts`). مدخل الجدول
  المرفوض خارجها يُرد بـ422. ليست قرارًا تجاريًا نهائيًا؛ تُعدل القيمتان بقرار واحد
  دون تغيير المنطق.
- مدة الانتقال **0** حتى اعتمادها. الفترات نصف مفتوحة `[start, end)` في القيد والـSlots،
  فيُسمح بموعدين متتاليين.
- شبكة بدايات الـSlots **30 دقيقة** (`SLOT_STEP_MINUTES`)، ونطاق الاستعلام **14 يومًا** كحد أقصى.
- أولوية الاستثناءات: الحجب يغلب دائمًا. تُطرح كل فترات `unavailable` (ويوم الحجب
  الكامل يمسح اليوم)، ثم تُضاف الإتاحة الإضافية خارج المحجوب فقط، ثم يُدمج
  المتداخل ويُقص الكل لنافذة النهار. حُسمت 2026-10-11.
- الجدول الأسبوعي: حتى 21 فترة إجمالًا وبحد أقصى 3 فترات لليوم الواحد بلا تداخل.
- الإلغاء متاح للعميلة والخبيرة صاحبة الحجز والمدير من `pending` و`accepted` فقط.
  إلغاء حجز `confirmed` (مدفوع لاحقًا) مرفوض حاليًا بـ409 حتى تُعتمد سياسة الاسترجاع —
  لا أثر مالي مخترع.
- الإكمال من `confirmed` فقط وللطرفين، بلا قيد توقيت (حُسم 2026-10-11)؛ الإكمال من
  `accepted` مرفوض بـ409 `INVALID_TRANSITION`.
- القبول يعيد فحص أهلية الخبيرة (اعتماد ونشاط وظهور) بقراءة مقفلة تتسلسل مع قرار
  تعليق متزامن؛ المعلقة ترد 409 `EXPERT_UNAVAILABLE` ويبقى الحجز `pending`.
- الضريبة لقطة صفرية (`vatRate 0.0000`) حتى اعتماد النموذج الضريبي. العمولة من
  `settings.booking_policy` وقت الإنشاء، بحساب صحيح (هللة/قرش) وتقريب نصف-لأعلى:
  `commission = round(price × rate / 100)`.
- انتهاء المهلة حدث نظام (`changed_by NULL`) عبر `src/jobs/expire-bookings.ts`،
  ويعمل دوريًا عبر `npm run worker` (انظر `web_app/backend/README.md`). شرط
  المهلة يعيش داخل `UPDATE` نفسه، فلا تُكتب مهلة مجددة أو تأكيد متزامن فوق قراءة
  قديمة. أي مسار يجد المهلة منتهية يحفظ الانتهاء وسجله وإشعاره في معاملة ملتزمة
  أولًا، ثم يرد 409 دون تراجع. القراءة الكسولة والانتهاء الجماعي بنفس العقد.

## APIs المنفذة (تحت `/api/v1`)

### التوفر

- `PUT /experts/me/availability` — استبدال الجدول الأسبوعي كاملًا (حتى 21 فترة، 3 لليوم،
  بلا تداخل داخل اليوم). `GET` للقراءة.
- `POST /experts/me/availability-exceptions` — `unavailable` للحجب أو `available` لإتاحة
  إضافية؛ وقتان فارغان معًا = اليوم الكامل. `GET` للسرد، `DELETE .../:id` للحذف.
- `GET /experts/:id/slots?serviceId&from&to` — عام، إرشادي فقط. يُعاد التحقق عند
  الإنشاء والقبول، والقيد هو الفيصل تحت التزامن.

### الحجز

- `POST /bookings` (عميلة) — `expertId, serviceId, addressId, startsAt, notes?`.
  الهوية من الجلسة، والعنوان ولقطته من عنوان تملكه العميلة، والسعر من عرض الخبيرة
  بالجنيه، والمدة من `services`. `pending` لا يحجز الفترة. `expiresAt` من مهلة القبول.
  ترويسة `Idempotency-Key` الاختيارية (UUID) تجعل إعادة الإرسال بعد timeout آمنة:
  التكرار يعيد الحجز نفسه، والطلب المتزامن يرد 409. التفاصيل في `docs/operations.md`.
- `GET /bookings` — نطاق المالك (عميلة/خبيرة)؛ المدير عبر `GET /admin/bookings` مع
  فلاتر `status, expertId, customerId`.
- `GET /bookings/:id` (ومسار المدير) — طرف الحجز أو مدير، مع `statusHistory`.
- `POST /bookings/:id/accept|reject` — الخبيرة صاحبة الحجز من `pending`، مع إعادة فحص
  الأهلية والحظر. القبول يعيد
  فحص التغطية والتداخل إرشاديًا ثم تحديثًا مشروطًا؛ رفض القيد `23P01` يُترجم
  `409 SLOT_TAKEN`. القبول يبدأ مهلة الدفع.
- `POST /bookings/:id/cancel` — الأطراف والمدير (ومسار `/admin/.../cancel` للمدير).
- `POST /bookings/:id/complete` — أي طرف من `confirmed` فقط.
- الأخطاء: `SLOT_UNAVAILABLE` خارج الدوام، `SLOT_TAKEN` عند التعارض، `BOOKING_EXPIRED`
  بعد المهلة، `INVALID_TRANSITION` لانتقال مرفوض، و404 لغير الطرف دون تسريب الوجود.

## التحقق

- `tests/integration/scheduling-bookings.test.ts`: خمس رحلات على PostgreSQL حقيقي —
  الجدول والاستثناءات وانعكاسها على الـSlots، الإنشاء بلقطات ثابتة والقبول، قبولان
  متزامنان (200 + 409 وبقاء الخاسر `pending`)، الصلاحيات والـState Machine وقوائم
  المدير، الرفض خارج الدوام والانتهاء الكسول عبر SQL ثم إعادة القراءة. الإكمال
  يمر بالدفع أولًا (409 من `accepted` ثم 200 بعد التأكيد).
- `tests/integration/consistency.test.ts`: سبع رحلات رجوع — انتهاء محفوظ رغم 409،
  سباق انتهاء/دفع، رفض المعلقة، أولوية الحجب عبر الـAPI وحد 3 فترات، إشعار
  الاسترجاع الذري، Worker متزامنان والتعافي، ورحلة متكاملة بالخدمات الفعلية.
  دالة `expireDue` الشاملة مغطاة باختبار وحدة بعقد مستودع مزيف لأن قاعدة التكامل
  مشتركة بين ملفات تعمل بالتوازي؛ لا يعدّل هذا الملف الصف المشترك للإعدادات لنفس السبب.
- migration `0007_availability_time_order.sql`: `end > start` للجدول والاستثناءات الجزئية.
